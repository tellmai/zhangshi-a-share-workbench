# V2.0实施分解与交付跟踪

需求基线：用户确认的55人日开发+10人日缓冲方案。以下记录功能落地位置和验收证据；估算不是已实际经过的天数。

| 阶段 | 原估算 | 已实现 | 验证与后续条件 |
|---|---:|---|---|
| P0 | 3日 | Git0.6.0基线，源文件清单、快照摘要、升级前备份，一键回归 | 真实快照三风格/四模板/旧财务回放逐项对比 |
| P1 | 7日 | Pydantic契约、SQLite追加版本、不可变证据、Parquet及旧资料幂等迁移 | 原文件摘要、二次迁移不新增、恢复后对象核验 |
| P2 | 7日 | 能力协议、区间历史、来源熔断、核验日历入口、代码顺序补齐与原因 | 免费源的历史证券状态/题材/公告/公司行为仍不足；不能将“接口实现”视为历史数据验收 |
| P3 | 6日 | 分级质量、独立进程、去重/租约/心跳/检查点、Windows隐藏调度、备份恢复 | 演练中断重领、重复提交、整批回滚；系统调度默认关闭 |
| P4 | 6日 | 复用公共特征、统一新范围、三日持续性、重叠组、角色及缺失解释 | 同输入确定性、未来数据截断和旧公式基线 |
| P5 | 5日 | 主线回踩、弱转强前置观察、证据卡和费用整手/组合约束 | 资金不足一手、回撤、同组限制等边界；不启用分钟确认 |
| P6 | 8日 | 历史可见版本、严格日线情景、日期费用、实验尝试、隔离分窗、滚动/压力测试 | 停牌与未知缺口、次日/T+1/限价、冻结复现；真实历史样本验证仍待数据积累 |
| P7 | 5日 | 人工/影子/演示账本、CSV预览、修订、现金、FIFO、退出计划、估值及执行偏差 | 系统外成交、重复回执、无对应买入、错误更正与核对 |
| P8 | 5日 | 新工作台/持仓/任务页，历史查询、共享清单、原页面兼容、导出 | HTTP和桌面调用同服务；实际浏览器及桌面流程验收 |
| P9 | 3日 | Python3.12运行时、版本化便携包、兼容安装脚本、后台入口、手册 | 当前Windows机器隔离数据烟测和安装演练；干净Windows参考机须另行验收 |
| 缓冲 | 10日 | 用于缺陷、源变化、迁移与性能修复 | 不折算为策略有效性观察期 |

## 交付后按依赖执行的详细计划

| 顺序 | 工作 | 产物与完成条件 |
|---|---|---|
| 1 | 在常用Windows设备安装/使用新入口，核对data目录；先创建备份 | 旧策略/结果可读取，报告与账本导出可打开 |
| 2 | 按真实来源核验当年交易日历；运行基础采集和代码队列 | 每日报价覆盖、限价、状态、分类及来源有记录；缺失可定位 |
| 3 | 核对实际账户资金、佣金、过户费、成交及初始持仓 | 账本现金和数量对账，费用配置版本冻结；未完成继续假设账户 |
| 4 | 根据接口逐项选择可选授权历史数据并验收 | 样本覆盖上市/退市/ST/停牌/题材变更/公司行为，带可见时间及授权能力说明 |
| 5 | 导入隔离的历史验证集，运行区间预检和严格实验 | 不截短区间、不混供应商复权、不用晚到状态驱动早盘；全部缺失明示 |
| 6 | 冻结假设、参数、基准和尝试登记，按时间开展样本外/滚动/成本压力研究 | 保留所有尝试；样本不足不报告策略有效，200事件只是初步检查 |
| 7 | 最终规则冻结后真实记录至少30个连续交易日 | 当日发布、质量、任务和影子记录可复现；规则改变另开观察版本 |
| 8 | 在4核16GB SSD和干净Windows环境测安装/升级/恢复/性能 | 记录配置、P95和日级计算实测；完成断网、休眠、进程异常恢复 |
| 9 | 满足数据与样本条件后再接入分钟/竞价 | 启用弱转强需独立的数据、路径和前瞻验证，不自动改变已发布规则 |

运行证据以`validation-v2.json`、`validation-v2-regression.json`及`validation-v2-desktop.json`等为准。前瞻时间、外部数据授权和干净机器验收属于外部条件，不通过回填测试结果宣称完成。

## 保留与回退

升级前Git基线2ccc37a及build/baseline-0.6.0保留；原0.6.0程序和安装包保留。原行情、策略、回测和报告JSON原位保留。新模块全部数据位于data/v2，恢复写入空目录。服务接口可按原入口运行旧功能；不需要切换到新引擎才能读取旧结果。
